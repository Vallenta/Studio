# Vallenta Studio — Roadmap

A forward-looking list of features planned for the Vallenta Studio extension. It's the single place to see what's planned and in progress; for features that have already shipped, see the [Changelog](CHANGELOG.md) and the [Feature Matrix](docs/feature-matrix.md).

This roadmap is **subject to change** and intentionally carries **no committed delivery dates** — priorities shift as the extension evolves and in response to user feedback.

**Status:** 📋 Planned · ✅ Recently shipped

## 📋 Planned

- **Delphi Breakpoints view** — A dedicated breakpoints panel that groups breakpoints by project and file, with custom labels and bulk enable / disable / delete — a clearer alternative to the generic Breakpoints list.
- **Symbols for source-less units (DCU)** — Hover, completion, and go-to-definition for units that ship only as compiled `.dcu` — RTL/VCL/FMX without source, and closed-source third-party libraries.
- **macOS (Apple Silicon)** — Editing and IntelliSense — hover, completion, go-to-definition, Find All References, diagnostics, and semantic highlighting — on Apple Silicon Macs. Building and debugging remain Windows-only.
- **Code formatter** — Format your Pascal source with a choice of engine: a built-in formatter (the default — works offline, with no extra install, and the only one that can format just the selected lines) or an external command-line formatter you already use (pasfmt, Jedi Code Format or Free Pascal's ptop). Format the whole document or a selection, with optional format-on-save. A later update will add extensive style options — per-block indentation, one-line `begin`/`end` handling, casing, spacing, and alignment.
- **Help for the symbol under the cursor (F1)** — F1 in a Pascal editor opens the Delphi help topic for the symbol at the cursor, the way the IDE does — including an inherited member, resolved to the ancestor that declares it. Topics come from the local help files of your Delphi installation, and from DocWiki for the versions that ship none. A later update adds a read-only help viewer inside VS Code, so a topic opens beside your code instead of in a separate window.

## ✅ Recently shipped

A few highlights — see the [Changelog](CHANGELOG.md) for the full history.

- **Visual form designer** — Edit `.dfm` forms without opening the Delphi IDE, working on the real form with real component instances rather than a preview or a wireframe: select, move, resize and align controls, drop new ones from a component palette, edit properties in an object inspector, and create or jump to event handlers — with the code side kept in your `.pas` by Vallenta Studio, so renaming a component renames its field and its handlers with it. Data modules and frames are covered alongside forms, and a saved `.dfm` matches what the IDE would have written for the same edit, down to components the designer does not know, which are preserved untouched. Third-party component packages are loaded from your Delphi installation, so you design with your own palette and not only the stock VCL. The designer opens in its own window first; editing inside a VS Code tab, and FMX forms, come later.
- **Debug Delphi Linux64 applications** — Cross-compile on Windows, then deploy, run and debug on a Linux machine, driven from VS Code on your Windows PC: breakpoints, stepping, call stack, locals and Watch with Delphi expressions, and program output. Your Delphi installation, your editor and the debugger all stay where they are — only your program runs on Linux. On the Linux side you run a single file: **VallentaAgent**, one static binary with no dependencies. Start it, paste the pairing token it prints into Vallenta Studio once, and it manages debug sessions from then on — no extra server software on the target, and no per-project setup. Vallenta Studio also fetches the Linux system libraries your build needs, so linking a Linux64 project works without registering an SDK. The first release covers console and server applications on Ubuntu 22.04 and 24.04, Debian 12 and 13, Rocky Linux 9 and 10 — RHEL and Alma of the same major included — and openSUSE Leap 16.0, with further distributions and older Delphi versions added as each is verified; a distribution outside that list can be imported from the target machine itself; attaching to an already-running Linux process come later.
- **Unused units: inline-function awareness** — The unused-units hint follows the Delphi compiler's inline expansion rule. A unit needed only so an `inline` method can be expanded — `Contnrs` when calling `TObjectList.Add` on a field typed in another unit, for example — is no longer reported as unused, and neither are the ancestor units an inline method's body relies on. Removing such a unit triggers compiler hint H2443 and loses the inlining.
- **Debugging for AI agents over MCP** — The MCP server gains debugging: an agent launches the active project or attaches to a running process, sets breakpoints with Delphi-syntax conditions, hit counts and logpoints, runs and steps with each stop returned in the reply, and reads the call stack, threads, locals, expression values, the current exception and the program output. It drives the same debug session shown in VS Code's Run and Debug view, so every stop is visible and the session can be paused or ended from the IDE at any time. Part of the MCP server (Pro).
- **Delphi expressions in the debugger (beta)** — Watch, hover, the Debug Console and breakpoint conditions read Delphi expressions: `Value = 10`, `Name = 'hello'`, `and`/`or`/`not`, and member access written with a dot. The underlying debugger's C++ syntax — `x == 5` and `->` — is no longer required anywhere, and string comparisons work on `string`, `AnsiString`, `UTF8String` and `WideString` variables alike. On by default; `vallenta.studio.debug.delphiExpressionEvaluator` turns it off.
- **XML documentation comments** — A `///` block written above a declaration appears in the hover popup under the signature, on the highlighted entry in code completion, and in the parameter hint while an argument list is being filled in. That covers the descriptions Embarcadero ships across the RTL, VCL and FMX as well as the documentation in your own code. The details pane beside the completion list now shows what hovering the symbol in source shows — signature, visibility, declaring file, inherited-from, overloads and the documentation — and `vallenta.studio.documentation.enabled` turns the display off.
- **MCP server for AI agents** — AI assistants that speak the Model Context Protocol — GitHub Copilot agent mode, Claude Code — now work from Vallenta Studio's resolved Delphi model instead of re-parsing your source: find a symbol, Find All References, find implementations, go to definition, implementation or declaration, code completion, hover info, document outline, diagnostics, and the lines your `{$IFDEF}`s switch off, plus the active project's units, configuration, platform and search paths, and starting a build and reading back its errors and warnings. Reading and building only — no editing or refactoring over MCP; debugging followed separately, above. The server runs locally on `127.0.0.1` and requires a token; VS Code 1.102 and later discover it automatically, and Claude Code is registered in one click from the settings page.
- **Attach to a running process** — Attach the debugger to an already-running Windows process by its process ID, with breakpoints, stepping, and Watch.
- **Keyboard mappings editor** — A visual editor for the extension's keyboard shortcuts, grouped by function — Run & Debug, Build & Compile, Navigation & Search, Code Enhancements, Project & Files — with each group collapsible and every action showing its current key. One button applies the Delphi keymap: F9 Run, Ctrl+Shift+F9 Run Without Debugging, F5 Toggle Breakpoint, F8 Step Over, F7 Trace Into, Shift+F8 Run Until Return, F4 Run to Cursor, Ctrl+F2 Program Reset, Ctrl+F9 Compile and Shift+F9 Build, covering the Delphi IDE's Run and Project menus. A second button restores the standard VS Code keys. Click any shortcut to record a new one, with conflicts flagged as you type. An option confines those keys to Delphi context, so F9 runs your Delphi project in a Pascal file while your other projects keep the standard VS Code behaviour. A fresh installation gets the Delphi keymap automatically; updating never changes keys you already have. Every action remains available in VS Code's own Keyboard Shortcuts editor.
- **Parameter hints** — While filling in a function, method, or constructor call, see the callable's parameter list with the argument you are currently entering shown in bold. Every overload is listed — step through them with ↑/↓ — and the one matching the arguments you have typed so far is preselected. Methods, constructors, `inherited` calls and calls inside a `with` block are covered, and Ctrl+Shift+Space brings the hint back if you dismiss it.
- **Apply Signature** — Change a routine's signature on one side and apply it to the other. With the cursor in the implementation, Ctrl+Shift+Alt+C (or Ctrl+. → **Apply signature to declaration**) updates the declaration; with the cursor on the declaration, the same gesture updates the implementation header and leaves its body untouched. Parameters, return type, `procedure`/`function` kind, the `class` prefix and the calling convention are carried across, while what only a declaration can hold — visibility, `virtual`/`override` and parameter default values — is preserved. Overloads are handled without guesswork: the edited overload is identified by pairing the others, and when more than one candidate remains you are asked which to update instead of having one chosen for you. A counterpart that does not exist yet is created, including the `overload` directives Delphi then requires. It works on code that does not compile, which is the normal state after a signature edit. A companion hint flags a routine whose implementation no longer matches its declaration, so a mismatch is visible as you type rather than at the next build — on by default at information severity, with configurable severity.
- **Class completion (Ctrl+Shift+C)** — Declare a method on a class or record — or a routine in the unit's interface — then press Ctrl+Shift+C (or right-click → Complete Class at Cursor) to generate its empty implementation body and jump straight to it. It completes every unimplemented method of the type at the cursor at once — class methods, constructors, destructors, operators, overloads and generics included — and works for global routines too, leaving already-implemented methods untouched.
- **Unused variables** — An optional hint that fades local variables and constants that are declared but never used within a routine, so leftover declarations are easy to spot as you type — without waiting for a compile. Can also flag variables that are only ever assigned but never read, and unused parameters (which the Delphi compiler never reports). On by default at information severity, with configurable severity.
- **EurekaLog integration** — Post-process your builds with EurekaLog automatically after every successful build, with no per-project post-build events to maintain. Vallenta Studio detects the EurekaLog compiler matching your Delphi version and runs it as part of the build, with per-version configuration and live detection status on the extension's settings page. Only projects that already have EurekaLog enabled are processed; everything else is left untouched.
- **Unused units** — An optional hint that fades `uses`-clause units never referenced in a file — across both the interface and implementation sections — so dead unit references are easy to spot and remove. On by default at information severity, with configurable severity and an editable ignore list for side-effect units.
- **Rename a unit** — Rename a unit and have everything update in one step: the `.pas` file and its companion `.dfm`/`.fmx` form, the `unit` header, every `uses` reference across your `.pas`, `.dpr` and `.dpk` files, and the project file — from the editor (`F2` on the unit name) or by renaming the file itself. Each reference keeps its existing style: a short `Forms` stays short, a qualified `Vcl.Forms` stays qualified.
- **Locals in optimized builds** — Local variables, parameters and `Self` now show while debugging optimization-compiled builds, where many previously failed to display.
- **LSP cache folder** — The offline symbol cache for your project moves into a single hidden `.vsdcache` folder, instead of placing several cache files next to each `.dproj`. 
- **Rename Symbol** — Rename a symbol and have every reference updated across the project in a single step, using the native VS Code Rename (`F2`) command, including references inside `.dfm`/`.fmx` form files.
- **Semantic highlighting** — Resolver-driven coloring of types, methods, properties, parameters, and enum members, plus same-identifier occurrence highlighting and structural begin/end coloring.
- **Find All References** — Scope-aware reference search across the project, including matches inside `.dfm`/`.fmx` form files.
- **Find unit references** — Locate every place a unit is referenced across `uses` clauses (in `.pas`, `.dpr`/`.dpk`, and the unit header), matched by physical unit identity rather than name.
- **Semantic color themes editor** — A visual editor for recoloring semantic tokens without hand-editing JSON.
