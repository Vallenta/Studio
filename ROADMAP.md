# Vallenta Studio — Roadmap

A forward-looking list of features planned for the Vallenta Studio extension. It's the single place to see what's planned and in progress; for features that have already shipped, see the [Changelog](CHANGELOG.md) and the [Feature Matrix](docs/feature-matrix.md).

This roadmap is **subject to change** and intentionally carries **no committed delivery dates** — priorities shift as the extension evolves and in response to user feedback.

**Status:** 🚧 In progress · 📋 Planned · ✅ Recently shipped

## 🚧 In progress

- **Form designer in an editor tab** — A `.dfm` form opens in a VS Code editor tab instead of a separate window, showing the full designer: component palette, design surface, object inspector and messages. Drop-down lists, menus and property dialogs appear inside the same tab, and no designer window appears on the desktop or the taskbar. Undo, Redo, Save, Revert and the unsaved-changes marker work as in any other VS Code editor. A switch turns tab mode on; the separate designer window remains the default.

## 📋 Planned

- **Delphi Breakpoints view** — A dedicated breakpoints panel that groups breakpoints by project and file, with custom labels and bulk enable / disable / delete — a clearer alternative to the generic Breakpoints list.
- **Symbols for source-less units (DCU)** — Hover, completion, and go-to-definition for units that ship only as compiled `.dcu` — RTL/VCL/FMX without source, and closed-source third-party libraries.
- **macOS (Apple Silicon)** — Editing and IntelliSense — hover, completion, go-to-definition, Find All References, diagnostics, and semantic highlighting — on Apple Silicon Macs. Building and debugging remain Windows-only.
- **Code formatter** — Format your Pascal source with a choice of engine: a built-in formatter (the default — works offline, with no extra install, and the only one that can format just the selected lines) or an external command-line formatter you already use (pasfmt, Jedi Code Format or Free Pascal's ptop). Format the whole document or a selection, with optional format-on-save. A later update will add extensive style options — per-block indentation, one-line `begin`/`end` handling, casing, spacing, and alignment.
- **Help for the symbol under the cursor (F1)** — F1 in a Pascal editor opens the Delphi help topic for the symbol at the cursor, the way the IDE does — including an inherited member, resolved to the ancestor that declares it. Topics come from the local help files of your Delphi installation, and from DocWiki for the versions that ship none. A later update adds a read-only help viewer inside VS Code, so a topic opens beside your code instead of in a separate window.
- **Language server rewritten in Rust** — The language server behind hover, completion, navigation, Find All References, diagnostics and the refactorings is being rewritten in Rust, feature for feature and with the same results, so nothing changes in how the editor features behave. The server becomes a single executable that starts without loading a .NET runtime, in place of the bundled runtime folder shipped today, and shares its code base with the debug-information tooling that is already written in Rust. An opt-in preview build will be offered for testing before the new server becomes the default, and the current server remains selectable for one release afterwards.

## ✅ Recently shipped

A few highlights — see the [Changelog](CHANGELOG.md) for the full history.

- **Code folding and `{$REGION}`** — Pascal code folds by its syntax: routines, types, sections, `uses` clauses, blocks, statements and comments, and each branch of an `{$IFDEF}` block. `{$REGION}` … `{$ENDREGION}` blocks fold, and a folded region shows its caption, styled by a setting on the settings page. Region captions can also appear as minimap labels, and `{$REGION}` blocks as groups in the Outline view.
- **Delphi 2007** — Delphi 2007 installations are detected, and their projects build, index, run and debug from the extension. Project Options opens a Delphi 2007 project read-only.
- **MCP server for AI agents** — AI assistants that speak the Model Context Protocol, such as GitHub Copilot agent mode and Claude Code, work from Vallenta Studio's resolved Delphi model instead of re-parsing the source: find a symbol, Find All References, find implementations, go to definition, implementation or declaration, code completion, hover info, document outline, diagnostics and the lines switched off by `{$IFDEF}`, plus the active project's units, configuration, platform and search paths, and starting a build and reading back its errors and warnings. An agent also debugs: it launches the active project or attaches to a running process, sets breakpoints with Delphi-syntax conditions, hit counts and logpoints, runs and steps with each stop returned in the reply, and reads the call stack, threads, locals, expression values, the current exception and the program output, in the same debug session shown in VS Code's Run and Debug view. No editing or refactoring over MCP. The server runs locally on `127.0.0.1` and requires a token; VS Code 1.102 and later discover it automatically, and Claude Code is registered in one click from the settings page. Pro.
- **Visual form designer** — Edit `.dfm` forms without opening the Delphi IDE, working on the real form with real component instances rather than a preview or a wireframe: select, move, resize and align controls, drop new ones from a component palette, edit properties in an object inspector, and create or jump to event handlers — with the code side kept in your `.pas` by Vallenta Studio, so renaming a component renames its field and its handlers with it. Data modules and frames are covered alongside forms, and a saved `.dfm` matches what the IDE would have written for the same edit, down to components the designer does not know, which are preserved untouched. Third-party component packages are loaded from your Delphi installation, so you design with your own palette and not only the stock VCL. The designer opens in its own window first; editing inside a VS Code tab, and FMX forms, come later.
- **Debug Delphi Linux64 applications** — Cross-compile on Windows, then deploy, run and debug on a Linux machine, driven from VS Code on your Windows PC: breakpoints, stepping, call stack, locals and Watch with Delphi expressions, and program output. Your Delphi installation, your editor and the debugger all stay where they are — only your program runs on Linux. On the Linux side you run a single file: **VallentaAgent**, one static binary with no dependencies. Start it, paste the pairing token it prints into Vallenta Studio once, and it manages debug sessions from then on — no extra server software on the target, and no per-project setup. Vallenta Studio also fetches the Linux system libraries your build needs, so linking a Linux64 project works without registering an SDK. The first release covers console and server applications on Ubuntu 22.04 and 24.04, Debian 12 and 13, Rocky Linux 9 and 10 — RHEL and Alma of the same major included — and openSUSE Leap 16.0, with further distributions and older Delphi versions added as each is verified; a distribution outside that list can be imported from the target machine itself; attaching to an already-running Linux process come later.
